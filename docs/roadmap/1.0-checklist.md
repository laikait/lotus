# 1.0 acceptance checklist

Checked against the repository on 2026-11-25, one line per criterion of spec §21 (and the §22 items that have already been built). Status: **done** (built, tested, documented), **partial** (usable, with a named gap), **missing** (not started).

## Summary

| | Count |
|---|---|
| Done | 9 |
| Partial | 10 |
| Missing | 2 |

The core server is far along: everything that serves a request (HTTP/1.1, HTTP/2, HTTP/3, TLS, ACME, vhosts, static files, routing, PHP, proxy, cache, compression, limits, metrics, control channel) exists and is tested. What is missing is mostly around the edges of 1.0: the formatter, application templates, binary upgrade, the network admin API, mTLS and the audit log, native packages, benchmarks and soak tests, the module interfaces, and the external security review.

## Already built from the 1.x list (§22)

- Nginx configuration translator (`lotus compat nginx convert`).
- Not started: Apache translator, extension framework (Wasm and out-of-process), WAF integration, Tier 1 promotion of FreeBSD and Windows.

## Suggested order for the rest

1. **Small and visible:** `lotus config fmt`, `lotus config migrate` (version 1 only for now), the quick start and operations guides, the generated directive reference (from the registry; `docs/configuration/directive-template.md` already defines the format).
2. **Proof that it works:** application templates and tests for WordPress and Laravel first (they exercise `.htaccess`, uploads, permalinks), then Symfony, Drupal, Joomla; benchmark harness and methodology; the 1,000-reloads test; a soak run script.
3. **Operations:** binary upgrade on Linux and FreeBSD; filesystem cache tier; `.deb` and `.rpm` (nfpm) and the signed Windows build; FreeBSD in CI.
4. **Security features:** mTLS, audit log, PROXY protocol, a third DNS provider, the network admin API.
5. **Decision needed:** item 16 (module architecture in 1.0 or 1.x).
6. **Last:** the security suite as a named job, then the external review with a release candidate.
